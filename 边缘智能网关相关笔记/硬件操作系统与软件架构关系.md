# 工业边缘智能网关：硬件、操作系统与网关软件关系总结

## 核心关系

工业边缘智能网关不是 RK3588，也不是 OpenHarmony。

```text
硬件平台
RK3588 / 龙芯 / x86
        ↓
操作系统
OpenHarmony / Linux发行版
        ↓
平台适配层
串口 / CAN / Ethernet / Modbus / MQTT / OPC UA
        ↓
网关核心业务层
统一数据模型
数据质量检查
数据预处理
时序窗口
特征提取
状态判断
事件输出
```

真正长期需要积累和复用的是 **网关核心业务层**。

## 哪些部分应平台无关

例如模块尽量只依赖标准 C++：

```text
DataPoint / Unified Data Model
QualityChecker
Filter
RingBuffer
Sliding Window
FeatureExtractor
State / Rule Evaluator
Event Model
```

原则：

> 输入标准数据，输出处理结果，不关心运行在 RK3588、龙芯还是 x86。

## 哪些部分与系统/硬件有关

```text
串口 / RS485
CAN
GPIO
网卡
设备驱动
文件系统
OpenHarmony N-API / ArkTS
RKNN Runtime
RK3588 NPU
龙芯专用运行库或加速器
```

建议项目结构：

```text
edge_gateway/
├── core/          # 平台无关
│   ├── data_model
│   ├── quality
│   ├── preprocess
│   ├── timeseries
│   ├── feature
│   └── decision
│
└── platform/      # 平台相关
    ├── openharmony/
    ├── linux/
    └── hardware/
```

## 更换平台时什么变、什么不变

当前：

```text
RK3588 + OpenHarmony
```

以后可能：

```text
龙芯 + Linux
```

基本不变：

```text
数据模型
数据质量
滤波
滑动窗口
特征提取
状态判断
```

需要重新适配：

```text
编译工具链
串口 / CAN / 驱动
系统接口
AI Runtime
硬件加速
```

注意：

> **源码可移植，不代表二进制可直接运行。**

RK3588 通常是 ARM64，龙芯通常是 LoongArch，同一套 C++ 源码需要针对不同平台重新编译。

## OpenHarmony 在项目中的角色

OpenHarmony 提供：

```text
进程
线程
网络
文件系统
设备访问
系统服务
应用框架
```

但不会替项目完成：

```text
数据清洗
数据质量判断
滑动窗口
特征提取
异常判断
```

这些仍然属于工业边缘智能网关自己的业务逻辑。

## 后续编程原则

```text
协议与算法解耦
硬件与业务逻辑解耦
操作系统与核心算法解耦
预处理与模型推理解耦
平台相关代码集中管理
```

理想目标：

```text
RK3588 + OpenHarmony ┐
龙芯 + Linux          ├──→ 同一套 Gateway Core
x86 + Ubuntu         ┘
```

也就是说：

> **换硬件平台，不应该导致预处理、特征提取和状态判断全部重写。**

## 当前项目定位

现在重点开发两部分：

```text
① Gateway Core
统一数据模型
数据质量
预处理
时序窗口
特征提取
状态判断

② Platform Adapter
先适配 RK3588 + OpenHarmony
```

核心层尽量保持标准 C++，平台层负责把真实设备数据送入核心，再把结果输出到 MQTT、数据库、UI 或后续 AI 模块。

## OpenHarmony 的分布式软总线

```
  应用层                                              
  调用统一 API，不关心底层                          

  分布式软总线                                        
  ├── 设备发现（发现附近设备）                       
  ├── 设备组网（自动连接）                           
  ├── 数据传输（统一接口）                           
  └── 服务调用（远程调用像本地一样）                 

  通信协议层                                          
  ├── Wi-Fi                                           
  ├── 蓝牙                                            
  ├── 以太网                                         
  └── 其他                                            

  硬件层                                              
  手机、平板、电视、传感器、网关...                  
```
