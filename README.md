# heterogeneous-computing
先看了工业数据采集、数据清洗、滤波、时序数据处理、滑动窗口这些比较基础的内容，之后开始往边缘侧 AI 推理方向，重点关注RK3588、RKNN、CPU/NPU异构计算这些内容。再往后主要在看模型部署、算子/子图划分、CPU与NPU之间的性能差异、数据传输开销，以及多模型并发、优先级、动态负载和任务调度等问题。

现在已经从“什么任务适合 CPU、什么任务适合 NPU”学习到了**怎么进行有效划分与调度**。不再是简单的分工，而是要判断模型或任务**在哪里切、切多细、切过去是否值得**。比如某个算子在 CPU 上单独执行更快，但并不代表应该迁移到 CPU，还要把 Tensor 传输、格式转换、同步和 Runtime 切换等代价考虑进去。

可能还要学习**最佳划分粒度**。粒度太细虽然灵活，但应该会增加CPU/NPU频繁切换与数据搬运；粒度太粗虽然开销低，但有可能限制资源的利用。因此应通过 Profiling 建立子图 开销成本，由全局 Scheduler 结合 A55/A76、NPU Core0~2 （我暂时以3588为例的硬件资源进行假设）的资源状态（当前的温度、负载、队列等等）做统一决策。

对于评价指标：重点可能考虑延迟，还可以分析吞吐、能耗、资源利用率传输代价等等。

现在正在github上找一些示例项目和demo,主要围绕NPUcore的选择和CPU-NPU任务的分配。
